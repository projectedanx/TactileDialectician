# KIRA-7 Implementation Checklist: Enforcing the Epistemic Matrix

This checklist ensures that any workflow generated by or integrated with KIRA-7 strictly adheres to the deterministic boundaries of the Feishu/Lark Open Platform.

## 1. Requirement Capture (The Scope Isolation Gate)
- [ ] **Event Trigger Defined:** The exact API event (e.g., `im.message.receive_v1`) has been explicitly identified.
- [ ] **Scope Declaration Block Present:** Every required scope (e.g., `im:message`, `im:message:send_as_bot`) is explicitly listed in the output for the human to configure in the Developer Console.
- [ ] **Environment Acknowledged:** The deployment environment (local ngrok, cloud server) is specified, and HTTPS requirements are enforced.

## 2. Webhook Sovereignty (Zero-Trust Ingress)
- [ ] **URL Verification Challenge Handled:** The endpoint immediately echoes `challenge` when `type === 'url_verification'`.
- [ ] **AES Decryption Implemented:** The payload is AES-256-CBC decrypted if the `Encrypt Key` is configured. Raw bodies are not treated as JSON prematurely.
- [ ] **Signature Verification Mandated:** `X-Lark-Signature` is computed via `SHA256(timestamp + nonce + encrypt_key + raw_body)` and strictly validated.
- [ ] **Replay Protection Active:** Timestamp freshness is verified (`|now - ts| < 300` seconds).

## 3. Token Primacy (Lifecycle Management)
- [ ] **Caching Layer Exists:** `tenant_access_token` and `app_access_token` are cached (Redis or in-memory lock).
- [ ] **TTL Safety Buffer:** Tokens are cached with a TTL strictly less than 7200 seconds (e.g., 6900 seconds) to prevent edge-case expirations during API transit.
- [ ] **No Static Tokens:** Tokens are never hardcoded as static strings in the application logic.

## 4. UI/Card Generation (DCCDSchemaGuard)
- [ ] **Two-Pass Generation Cycle Used:** The logic flows from a natural language draft (THINK) into schema-constrained execution (CODE).
- [ ] **Feishu Schema Compliance:** The output is strictly Feishu Card JSON v2.0. (No Microsoft Adaptive Card syntax).
- [ ] **Envelope Correctness:** Cards are wrapped in the correct message structure (e.g., `msg_type: "interactive"` with a nested `card` object).

## 5. Personality & Loop Containment
- [ ] **Petzold Sequence Adherence:** The workflow explicitly uses `[THINK PHASE]`, `[WRITE PHASE]`, `[CODE PHASE]`, and `[IMMUNE REVIEW]` markers.
- [ ] **Code Sterility:** The generated code contains zero persona chatter. The gritty tone is isolated to the THINK/WRITE phases.
- [ ] **Scar Review:** The output is cross-referenced against the Symbolic Scar Registry (SCAR-001 through SCAR-007) during the Immune Review.
